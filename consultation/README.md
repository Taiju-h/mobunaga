# 編成相談

## 目的
土地4〜8／対人戦／特定メタの入口、家門別の全武将選択、テンプレート採用件数による人気順、相方逆引き、編成ごとの戦法・能力振り・兵学・条件を提供する。

## データ
- 武将: assets/database.live.json（404時のみ database.json）。assets/s4-additions.json は空欄の補完用。ライブデータを優先。
- S1〜S3: 既存 formations.live.json（404時のみ formations.json）。
- S4人気順: assets/s4-templates.json の105掲載表のみ。記事本文・FAQ・他サイトの5件を母数へ混ぜない。
- 本館用 formations.json にも105件を追加。season-context.js がS4スナップショットを同じIDでマージするため、古いMySQLエクスポートでも閲覧できる。MySQLへ直接書き込む変更ではない。
- S4原典: https://www.sanguo-zhi.com/entry/s4-template/ （2026-10-01取得）
- 105編成、315武将枠、全て既存武将IDと対応。コスト合計は全編成一致。
- 勇猛無前／三河弓兵／直言極諫／赤備え は出典表記を保持し、未確定の戦法IDを割り当てない。
- 採用件数: 掲載表1件につき各武将1回。同じ三人でも戦法・兵種等が異なる別掲載案は別件。本文の出現回数ではない。
- 同率はふりがな順。0件を除外しない。家門は武将マスターの family に基づく。
- 表示シーズンまでに登場する全武将を対象とする。人気順と編成一覧は選択シーズンの完全一致。mobunagaSeason / mobunaga_season を本館と共有。
- 土地ごとの兵損・勝率・連戦可否は未集計。掲載Tierは出典の評価であり相性判定ではない。
- 元のSites版はレビュー用として保持。本番の正はこのリポジトリ。

## 検証
JavaScript構文・実データの判定ロジックに加え、Chromiumで三つの操作経路、選び直し、除外/復帰、複数敵、0件、シーズン境界、モバイル幅を検証。本番サーバーへの反映は別途デプロイが必要。

既存テンプレートの掲載シーズンを登場時期の根拠として併用する。Tierが初めて付いたシーズンだけで登場時期を決めると、S1掲載済みの星4武将が消えるため。

## 2026-10-01: 目的別フロー
色・書体・ヘッダー・目的カード・編成カードは既存のデザインを維持し、相談条件を一段ずつ進める構成に変更。

- 土地攻略 → 土地4〜8 → 使いたい武将 → その他の武将を除外 → 編成一覧。
- 対人戦 → 使いたい武将 → したい対策（複数可・指定なし可） → 編成一覧。
- 対人メタ戦 → 敵テンプレート（1件以上・複数可） → 使いたい武将 → したい対策 → 編成一覧。
- 軸の武将は明示選択。検索や家門フィルターで選択を自動変更しない。
- 武将は全員を残した状態から未所持・使用不可の武将を除外。軸は除外不可。戻す操作・残り編成数・0件時の再選択を提供。
- 前の工程を変更したら後の工程を未完了に戻す。シーズン変更は全選択をリセットし、URL・本館リンクにも反映。

### 判定の根拠
`evidence.js` はマスターの効果文を確認した戦法ID・固有戦法ID・無凸特性名を対応付ける。単語が出ただけでは対策に数えない。戦法名による照合は、IDが見つからず同シーズンの名前が一意の場合のみ。

対策は「すべて」か「いずれか」で絞り込み。本人限定・確率発動・準備ありも検討候補に含め、原効果・所持武将・対象条件・出典を候補に併記する。高凸特性を無条件に有効扱いしない。謙信の混乱耐性は全阻害対策に拡張せず、大祝鶴の被通常攻撃利用は防御手段に数えない。

敵テンプレートごとに、確認済みの制御、装備能動・突撃戦法、回復効果から対策の着眼点を抽出。自軍候補の手段と対応させ、未収録の効果数も表示する。敵の速度・耐性・兵種・発動順を含む戦闘シミュレーションではなく、対面勝率や有利判定は出さない。

並び順は指定対策の一致数 →（メタ戦のみ）選んだ相手の着眼点に手段がある相手数 → 掲載Tier → 出典掲載順。候補0件で除外や対策を勝手に緩めない。

土地レベルは攻略資料へのリンク・出撃確認項目に反映。土地ごとの戦報と掲載テンプレートを自動照合した推薦ではない。S4土地4・5・6は既存攻略ページへ案内し、他は資料未照合と表示する。

### 再現テスト
リポジトリを `python -m http.server 8765 --bind 127.0.0.1` で配信し、Playwright/Chromiumがある環境で `node tests/consultation-flow.cjs` を実行する。必要に応じて `NODE_PATH`、`CONSULTATION_TEST_URL`、`CHROMIUM_EXECUTABLE_PATH` を指定可能。除外・対策根拠・シーズン境界のロジックと、三経路、複数敵、戻る/変更、0件、スマートフォン幅を確認する。

## 二人固定・期待値診断・戮力同心の差し替え案

- 武将を1〜2名固定し、掲載編成は全員を同時採用するものに絞る。0件でも固定条件を緩めず、不足から探す候補を別に提示する。
- `advisor.js` はDOMに依存しない比較エンジン。`advisor-ui.js` が実能力値・装備2枠・被弾比重・阻害条件の編集、3人目の試算、掲載戦法の読み込みを担当する。
- 未所持は小さいカードへ移し、推薦・掲載編成・差し替え案から除く。`mobunagaAdvisorUnowned` に保存し復帰可能。固定中の武将は未所持指定より優先する。
- 補完候補は同家門、または会盟の必須条件を満たす武将だけを改善量で順位付け。同点は同時掲載数を使う。会盟の実効果はS3以降、異なる3家門、大将固有が能動/突撃、戦法の装備を満たす場合のみ大将固有へ13ポイントを加算する。副将の兵力順依存効果は未計算。

### ボーダーと仮定

Lv50素値・属性・目的・本人の掲載採用から自動選択した戦法2枠で開始し、実際の武勇/知略/統率を入力する。戦法はLv10係数。攻撃目安は武勇250以上・兵刃200%/T、知略250以上・計略200%/T、または武勇200以上・通常攻撃3回/T。兵刃と計略を混ぜて目安を満たしたことにしない。

必要回復の比較式は `敵基準率 × 被弾比重 × 150 / 統率 × 敵与ダメ低下後の倍率 × 味方軽減後の倍率`。これはゲームのダメージ公式ではない。初期基準はチーム全体200%/T、比重は現在診断中の人数で正規化する。1〜2名の途中診断と3名完成時では被弾配分が変わるため、完成後に確認が必要。低統率を固定条件で落とさず、軽減を先に適用して回復需要を下げる。受け役以外の被弾も別々に扱い、自己回復の余りを他の武将へ転用しない。

異なる軽減は乗算の仮定。各効果の対象数と有効ターンを反映する。同じ効果の再発動は更新として扱う。準備/再発動待機は有限ターンの確率過程で計算するが、準備中断・速度順・同一ターン内の先後は再現しない。制御確率の期間合成は独立近似であり、必須条件や勝率ではない。鉄壁は付与回数を出すが、消費順が不明なので必要回復から直接引かない。指揮回復は能動実行率の低下から独立、回復不可は別の入力で反映する。

**全効果の数値化は未完了。** レビューした効果のみモデル化し、未登録固有・特性・条件付き追加分・属性依存増分を明示する。未登録を「効果なし」と断定しない。兵種・コスト・属性バフ・耐性・発動順まで含む完全な戦闘シミュレーションではない。比較スコアは攻撃40、回復30、耐久/盾20、軽減8、制御2の仮配点。実測勝率を表さない。

### 長野業正の伝授戦法

戮力同心（S4・指揮）は本人の編成を要求せず装備候補にする。発動率・回復率とも統率依存だが、上昇式が未確認のため、Lv10表記値34%・82%を初期値にし、実機値の入力を提供する。統率を変えるだけで未知の上昇量を捏造しない。回復先は本人が最少兵力/他の二人/未確定の均等配分を切り替える。

出典: https://www.sanguo-zhi.com/wiki/tactic/naganonarimasa-rikuryokudoushin/

`replacementVariants` はS4掲載105編成の3名×2装備枠を各1枠だけ差し替え、630案を実行時に生成する（固定武将・未所持で絞り込み）。装備枠を増やさず、元の火力・回復・軽減・制御との変化を比較する。外す戦法が未モデル化なら損失評価は保留。原典データ・掲載Tierは書き換えず「原典とは別案」と表示し、選択後に3名を診断する。S3以前には生成も選択もできない。

## 属性・目的に合わせた初期戦法（2026-10-01）

`loadout.js` は、現在のシーズン、本人の掲載戦法採用数、武勇/知略/統率の適性、選択した目的・対策から2枠を選ぶ。重視属性は実能力値の最大値を初期選択に使い、ユーザー指定で固定できる。火力は兵刃/計略、属性依存が明記された補助はその属性を適性評価に使う。これは戦法候補の選定規則であり、未知のダメージ公式を補間するものではない。

- 属性一致を優先し、掲載採用、対策一致、土地用の回復・軽減を加点する。出典に載った戦法を無条件の最適解としない。
- 兵種未指定のため専用兵種戦法・内政・未収録効果は自動装備から除く。会盟以外の陣形も自動装備しない。手動選択は可能。
- 自動の戦法は部隊内で重複させず、手動指定済みの戦法も避ける。本人固有と同名の戦法を自動装備しない。
- 手動指定/掲載テンプレート読み込みは枠ごとに固定する。能力値・重視属性を変えても保持。自動に戻す操作を用意する。
- 診断の前に戦法名と選定理由を常時表示する。固定武将と推薦候補は両方装備込みで評価。推薦候補を足す比較では、固定武将の装備を保持する。
- 「同じ家門」は固定武将全員と同じ `family` の候補だけ。「会盟の陣」は全員が別の `family`、大将固有が能動/突撃、S3以降を必須とする。以前の `faction` による判定と補助点方式から変更。分類や固有種別が不明なら成立とみなさない。
- 会盟を選ぶと実際の2枠のうち1枠に会盟を入れる。空けられる自動枠がなければ装備枠不足を表示する。手動で会盟を入れた場合も推薦は会盟条件に限定する。同家門へ切り替えた場合は会盟を外して自動枠に戻す。
- 固定が1名の場合も、会盟候補は既存と別家門に限定し、3名完成まで効果を加算しない。固定が2名なら3人目を厳密に絞る。条件不成立/0件で条件を緩めない。
- シーズンを変えたら診断装備を初期化し、先のシーズンの戦法を持ち込まない。

検証: `node tests/loadout-model.cjs`（全137名の初期装備、属性/目的、手動保持、家門/会盟、固定装備、未所持、シーズン）と `node tests/loadout-ui.cjs`（画面操作・大将変更・スマートフォン幅）。以前の診断/フローのテストも併用。
